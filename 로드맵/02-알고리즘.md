# 02. 알고리즘 / 자료구조 로드맵 (8주 · 대기업 코테 대비)

- **목표**: 1~2개월 안에 대기업/IT 기업 코딩테스트 통과 (프로그래머스 Lv.2를 안정적으로, Lv.3 일부)
- **하루**: 60분 (개념 15 + 문제 40 + TIL 5) / **주말 모의 코테**는 별도 시간 확보
- **언어**: Python
- **문제 플랫폼**: **프로그래머스 위주** (코딩테스트 고득점 Kit → 카카오 기출 → 다른 기업 기출). 백준은 부족한 유형 보충용으로만
- **TIL 카테고리**: `Algorithm/`
- **우선순위 근거**: 1순위 = 시뮬레이션·구현·완전탐색·BFS·DFS (+ 스택/큐/해시/그래프 기초), 2순위 = DP·다익스트라 → 1순위가 기반이라 먼저

## 문제 푸는 규칙

1. 문제를 읽으면 **코드 전에 입력 크기 → 허용 복잡도**부터 말하기 (10^5면 O(N log N), 10^3이면 O(N²))
2. **30분** 고민해도 안 풀리면 풀이 보기 OK → 아무것도 안 보고 **다시 직접 구현** → 조건을 바꿔 **변형 1번** 풀기
3. TIL에는 "유형 / 핵심 아이디어 / 시간복잡도 / 틀린 이유" 4줄만
4. 틀린 문제는 **3일 뒤, 2주 뒤** 다시 풀기 (오답 노트)
5. 제출 전 **반례 3개** 손으로 확인: 최소 입력(빈 값, 1개), 최대 입력(시간), 중복·음수·같은 값
6. 프로그래머스는 **제출 전 "채점"의 히든 케이스**가 있으니, 틀리면 엣지 케이스부터 의심
7. 풀이는 **IDE 자동완성 없이** 프로그래머스 에디터에서 직접 작성

## 신호 → 알고리즘 치트시트 (직접 채우기)

| 문제에서 보이는 신호 | 먼저 떠올릴 것 |
|---|---|
| 최단 거리, 최소 횟수 (가중치 없음) | BFS |
| 가중치 있는 최단 경로 | 다익스트라 |
| 모든 쌍의 최단 거리, 정점 수 작음(≤ 500) | 플로이드-워셜 |
| "모든 경우" + N이 작음(≤ 20) | 완전탐색 / 백트래킹 |
| 정렬된 배열, 최댓값의 최솟값 | 이분 탐색 |
| 연속 구간, 부분 배열 | 투 포인터 / 슬라이딩 윈도우 |
| 구간 합 반복 질의 | 누적합 |
| 부분 문제가 겹침 | DP |
| 연결 여부, 그룹, 네트워크 개수 | Union-Find / DFS |
| 문제 설명이 길고 규칙이 많음 | 시뮬레이션 (조건 → 코드 1:1로 옮기기) |
| (직접 추가) | |
