## 병행 일정 (하루 6시간 이상, 평일만)

**2026-10-15(목) 시작**, 총 **36 평일 (약 7주)**, 끝나는 날은 12/03(목). 하루에 서로 다른 주제 3~4개를 병행하고, 한 파일의 Day를 하루에 2개씩 하기도 한다. 각 파일 맨 위 `start:`(시작일)와 `perday:`(하루에 하는 Day 수)를 바꾸면 위의 달력이 자동으로 다시 그려진다.

| 평일 번호 | 날짜 | 하는 것 | 학습량 |
|---|---|---|---|
| 1~7 | 10/15 ~ 10/23 | Python D1~7, SQL D1~7, 알고리즘 D1~7, Git D1~7 | 약 5시간 |
| 8~11 | 10/26 ~ 10/29 | Python D8~11, SQL D8~11, 알고리즘 D8~11, Linux D1~4 | 4.5~5시간 |
| 12~14 | 10/30 ~ 11/03 | Python D12~14, 수학 D1~3, 알고리즘 D12~14, Linux D5~7 | 약 5시간 |

| 32~36 | 11/27 ~ 12/03 | PyTorch D7~11, 알고리즘 하루 1문제 | 2~3시간 + **남는 3시간은 2단계(LLM 앱) 시작** |

선행 관계는 지켜진다. Docker는 Python Day 14(FastAPI) 이후에, PyTorch는 수학 Day 4~7과 ML 기초 Day 1~7 이후에 시작한다.

### 하루 시간표 (예시, 6시간)

| 시간 | 내용 |
|---|---|
| 09:00 ~ 10:00 | 알고리즘 1 Day (오전 집중) |
| 10:10 ~ 12:10 | 메인 과목 (Python 등 1 Day, 주제 2개) |
| 12:10 ~ 13:10 | 점심 |
| 13:10 ~ 15:10 | 서브 과목 1~2개 |
| 15:20 ~ 16:20 | 복습 + 미니 프로젝트 (일정 마지막 Day들) |
| 16:20 ~ 16:50 | **TIL 작성** + "확인" 질문 말로 답하기 |

속도가 빠른 만큼 **읽기보다 직접 코딩하는 비중을 높이고**, 확인 질문에 막히면 그 Day만 다음 날 첫 시간에 다시 한다. 일정이 밀리면 해당 파일의 `start:`를 미루거나 그 Day를 다음 평일로 넘긴다. 밀린 칸은 달력에 빨갛게 표시된다.
공휴일이 있으면 해당 파일 맨 위에 `skip: 2026-12-25` 처럼 적으면 그날을 건너뛴다.

이미 아는 주제는 Day를 건너뛰고 **"확인" 질문만 말로 답해 보고** 막히면 그 Day만 한다.

## Day 하나의 루틴 (공통)

1. **5분** 어제 TIL 한 줄 요약 읽기
2. **30~50분** 오늘 Day 학습 + 직접 손으로 실습 (읽기만 하면 안 남는다)
3. **5분** "확인" 질문에 소리 내어 답하기 → 막히면 내일 첫 줄에 복습 추가
4. **5~10분** TIL 작성 후 커밋

## 완료 기준

각 로드맵 마지막에 있는 **"이 정도면 점검 끝"** 항목을 설명 없이 말로 풀 수 있으면 해당 주제는 통과.
통과한 주제는 이 표에서 ~~취소선~~으로 표시하고 다음 단계(LLM 애플리케이션)에 집중한다.

## 공통 원칙

- 연습용 레포는 **개인 샌드박스 레포**에서만 만든다. 조직(회사/팀) 레포는 건드리지 않는다.
- 하루 빠지면 몰아서 하지 말고 **그 Day를 그대로 다음 날로 밀기**. 건너뛰지 않는다.
- 일주일의 마지막 Day는 복습/미니 프로젝트라서 여기서 포트폴리오 재료가 나온다.
