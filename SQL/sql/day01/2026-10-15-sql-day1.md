## ① SELECT 기본

### 배운 것
- 논리적 실행 순서: **FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY → LIMIT**
  - 작성 순서와 다름. 그래서 `WHERE`에서는 SELECT의 별칭을 못 쓰고, `ORDER BY`에서는 쓸 수 있음
  - (PostgreSQL은 `GROUP BY`에서도 별칭 허용: `GROUP BY ym` 동작 확인)
- `BETWEEN a AND b`는 양끝 **포함**
- `LIKE '김%'` 앞부분 일치, `_`는 한 글자
- `DISTINCT dept`는 NULL도 하나의 값으로 취급해 한 행으로 나옴
- **NULL 비교는 `= NULL`이 아니라 `IS NULL`**
  - `WHERE dept = NULL` → 0행 (NULL과의 비교는 참이 아니라 UNKNOWN)
  - `WHERE dept IS NULL` → 한소희 1행
- 정렬에서 NULL 위치: PostgreSQL은 `DESC`일 때 NULL이 **맨 앞**
  - `ORDER BY salary DESC LIMIT 3` → 급여 없는 임재현이 1등으로 나옴
  - `NULLS LAST`를 붙여야 의도한 Top 3

## ② 집계

### 배운 것
- `COUNT(*)`는 행 수, `COUNT(col)`은 **NULL 제외** 개수
  - 실측: 전체 9 / `COUNT(dept)` 8 / `COUNT(salary)` 8
- `AVG`, `SUM`, `MAX`, `MIN`도 NULL은 무시 (NULL 행은 평균 분모에도 안 들어감)
- `GROUP BY dept`에서 NULL은 하나의 그룹으로 묶임 (부서 없는 한소희 그룹)
- **WHERE vs HAVING**
  - `WHERE`: 그룹 만들기 **전에** 행을 거름 (집계함수 사용 불가)
  - `HAVING`: 그룹 만든 **후에** 그룹을 거름 (집계함수 사용 가능)
  - 예: 2022년 이후 입사자만(WHERE) 모아서 2명 이상인 부서만(HAVING) → 영업 2명
- 집계 안에 식도 가능: `SUM(qty * price)`로 고객별/월별 매출
  - 고객별 10만원 이상: A 290,000 / B 250,000 / C 160,000
  - 월별: 2026-09 400,000 / 2026-10 320,000

## 확인 질문 답변
Q. 실행 순서(FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY)를 말할 수 있나?
A. FROM(테이블 결정) → WHERE(행 필터) → GROUP BY(그룹화) → HAVING(그룹 필터) → SELECT(컬럼/별칭 계산) → ORDER BY(정렬) → LIMIT 순서.
   작성 순서(SELECT가 맨 앞)와 달라서, WHERE에서는 SELECT 별칭을 못 쓰고 ORDER BY에서는 쓸 수 있다.

Q. `WHERE`와 `HAVING`의 차이는?
A. 필터링하는 시점과 대상이 다르다. `WHERE`는 그룹화 **전**에 개별 행을 거르고 집계함수를 못 쓴다.
   `HAVING`은 그룹화 **후**에 그룹을 거르고 `COUNT(*) >= 2`처럼 집계함수를 쓸 수 있다.
   예: `WHERE hired >= '2022-01-01'`로 행을 먼저 줄이고, `HAVING COUNT(*) >= 2`로 인원 2명 이상인 부서만 남겼다.
   (행 조건은 가능하면 WHERE로 먼저 거르는 게 처리할 행이 줄어 유리하다.)
