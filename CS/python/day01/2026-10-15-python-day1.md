## ① 자료형과 mutable/immutable

### 배운 것
- `id()`와 `is`를 몰랐는데 알게 됨
  - `id(x)`: 객체의 고유 번호. 같은 객체면 같은 번호
  - `a is b`: 같은 **객체**인지 비교 (`id(a) == id(b)`와 같음)
  - `a == b`: **값**이 같은지 비교
  - `b = a`는 복사가 아니라 같은 객체에 이름을 하나 더 붙이는 것 → `b`를 바꾸면 `a`도 바뀜
  - `a.copy()`는 값이 같은 새 객체 → `a is c`는 `False`, `a == c`는 `True`
  - `is`는 보통 `None` 비교에만 사용 (`if x is None`)
- mutable / immutable
  - **mutable**(list, dict, set): 만든 뒤 그 객체를 **제자리에서 고칠 수 있음** (화이트보드)
  - **immutable**(int, str, tuple, bool, None): 고칠 수 없음. 바꾸려면 **새 객체를 만들고 이름만 옮김** (인쇄물)
  - mutable을 공유하면 한쪽이 고칠 때 다른 쪽도 영향을 받음, immutable은 공유해도 안전

  ```python
  a = [1, 2]; b = a
  b.append(3)          # 같은 객체를 고침
  print(a, a is b)     # [1, 2, 3] True

  s = "hi"; t = s
  t = t + "!"          # 새 객체를 만들고 t가 그쪽으로 이동
  print(s, t, s is t)  # hi hi! False
  ```
- `=` / 얕은 복사 / 깊은 복사
  - 리스트의 각 칸은 객체를 직접 품는 게 아니라 객체를 **가리키는 화살표**

  | | 겉(바깥 리스트) | 안쪽 객체 |
  |---|---|---|
  | `b = a` | 같은 객체 (이름만 추가) | 같은 객체 |
  | 얕은 복사 (`a.copy()`, `a[:]`, `list(a)`) | 새로 만듦 | **공유** |
  | 깊은 복사 (`copy.deepcopy(a)`) | 새로 만듦 | 전부 새로 만듦 |

  - 얕은 복사에서 **겉을 바꾸면**(추가/삭제/칸 교체 `c[1] = ..`) 원본은 그대로. 내 칸의 화살표만 바뀌기 때문
  - **안쪽을 고치면**(`c[0].append(..)`) 원본도 같이 바뀜. 같은 객체를 함께 가리키기 때문
  - 안쪽이 숫자/문자열 같은 immutable이면 얕은 복사로 충분
- 자료형별 분류

  | 구분 | 자료형 |
  |---|---|
  | immutable | `int` `float` `bool` `str` `tuple` `frozenset` `bytes` `None` |
  | mutable | `list` `dict` `set` `bytearray`, 직접 만든 클래스 인스턴스 |

- 자료형별 함정
  - **tuple 안에 mutable이 있으면**: `t = ([1, 2], 3)`에서 `t[0].append(99)`는 되고 `t[0] = [0]`은 `TypeError`. tuple이 고정하는 건 "칸이 가리키는 대상"이지, 그 대상의 내용이 아님
  - **`+=`는 자료형마다 다름**: list는 제자리 수정(id 유지, 다른 이름에도 영향), int/str은 새 객체(id 바뀜)
  - **dict의 key는 immutable만**: `d[[1, 2]] = ..`는 `TypeError: unhashable type: 'list'`. 내용이 바뀌면 hash가 바뀌어 찾을 수 없기 때문
- `a = 5` 다음 `a = 6`은 5를 고친 게 아니라 `a`의 화살표를 6으로 옮긴 것
  - 아무도 가리키지 않는 객체는 참조 횟수가 0이 되어 자동으로 메모리에서 정리됨 (`sys.getrefcount`로 확인)
  - 작은 정수(-5~256)는 미리 만들어 두고 재사용. 값 비교는 `is`가 아니라 `==`로
  - 문자열을 `+=`로 반복해서 이어 붙이면 매번 새 객체가 생겨 느림 → 리스트에 모아서 `"".join()`
- 시간복잡도 실측 (`complexity.py`, n=100,000 · 1000회)

  | 연산 | list | set / dict |
  |---|---|---|
  | `in` / 검색 | 0.52s, O(n) | 0.00002s, O(1) (약 2만 배 차이) |
  | `append`, `pop()` (끝) | 0.00001s, O(1) | - |
  | `insert(0)`, `pop(0)` (앞) | 0.02~0.03s, O(n) | - |

  - list는 연속 배열이라 앞을 건드리면 뒤를 전부 밀어야 하고, set/dict는 해시로 바로 찾음
  - 자주 "있는지 확인"하면 set/dict, 앞에서 넣고 빼면 `collections.deque`

### 막혔던 점 / 해결
- `b = a`가 얕은 복사인 줄 헷갈림 → 복사가 아니라 이름표 추가. 얕은 복사는 `copy()`처럼 겉 객체를 새로 만드는 것
- 얕은 복사인데 왜 칸을 교체하면 원본이 안 바뀌나 → 공유하는 건 칸이 가리키는 객체이고, 칸(화살표) 자체는 각자 가짐
- 함정 예: `[[0] * 3] * 3`은 같은 안쪽 리스트를 3번 가리킴 → `[[0] * 3 for _ in range(3)]`로 만들어야 함

## ② 제어흐름과 컴프리헨션

### 배운 것
- 제어흐름
  - `enumerate(seq)`: (인덱스, 값) 순회 / `zip(a, b)`: 두 시퀀스를 짝지어 순회
  - `continue`: 이번 회차 건너뜀 / `break`: 반복 종료
  - `for-else`: `break` 없이 끝까지 돌았을 때만 `else` 실행 ("못 찾았을 때" 처리)
- 컴프리헨션: for 루프를 한 줄로

  ```python
  result = [n * n for n in nums if n % 2 == 0]
  #         ①표현식   ②for     ③조건      (읽는 순서: ② → ③ → ①)
  {n: n * n for n in nums}   # dict 컴프리헨션
  {n % 3 for n in nums}      # set 컴프리헨션 (중복 제거)
  ```
  - 거르기만 할 때는 `for` **뒤**에 `if`: `[n for n in nums if n % 2 == 0]`
  - 값을 고를 때는 `for` **앞**에 `if-else`: `["짝" if n % 2 == 0 else "홀" for n in nums]`
  - 중첩은 바깥 루프가 먼저: `[v for row in matrix for v in row]` (복잡하면 일반 for 루프가 나음)
  - 2차원 배열은 `[[0] * 3 for _ in range(3)]` (줄마다 별개 리스트)
- 제너레이터 표현식: 대괄호를 소괄호로 바꾸면 하나씩 계산
  - `[x for x in range(10**6)]`: 100만 개를 전부 만들어 저장 → 약 8.4MB
  - `(x for x in range(10**6))`: 만드는 방법만 저장, 필요할 때 계산 → 192 bytes
  - 합계처럼 한 번 훑고 끝낼 때 유리: `sum(x for x in ...)`
  - **한 번 소비하면 비어 있음**: `sum(g)` 두 번째는 0. 여러 번 쓰려면 list로 만들거나 새로 생성
  - `sys.getsizeof`는 요소 객체 자체의 크기는 포함하지 않음
