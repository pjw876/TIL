## ① 빅오와 입력 크기

### 배운 것
- 빅오: 입력 크기 N이 커질 때 연산 횟수가 **어떤 속도로 늘어나는지**를 나타냄 (상수·낮은 차수는 버림)
- 코테 감각: 파이썬은 1초에 약 10^7~10^8 연산 → **N을 보고 허용 복잡도부터 말하기**

  | N | 허용 복잡도 |
  |---|---|
  | ≤ 20 | O(2^N), O(N!) 일부 |
  | ≤ 500 | O(N³) |
  | ≤ 3,000 | O(N²) |
  | ≤ 10^5 | O(N log N) |
  | ≤ 10^6~10^7 | O(N) |
  | ≤ 10^18 | O(log N) |

  - 계산표: `input_size.py` (N=10^5에서 O(N²)는 10^10이라 X, O(N log N)은 약 166만이라 OK)
- 파이썬 연산별 시간복잡도

  | 연산 | list | deque | set / dict |
  |---|---|---|---|
  | 끝에 추가/삭제 (`append`, `pop()`) | O(1) | O(1) | - |
  | 앞에 추가/삭제 (`insert(0)`, `pop(0)` / `appendleft`, `popleft`) | **O(n)** | **O(1)** | - |
  | `x in ...` | O(n) | O(n) | O(1) 평균 |
  | 인덱싱 `[i]` | O(1) | 가운데는 O(n) | - |
  | 정렬 `sort` | O(n log n) | - | - |
  | 슬라이싱 | O(k) | - | - |

- `list.pop(0)` vs `deque.popleft()` 실측 (`queue_compare.py`, N번 전부 빼기)

  | N | list.pop(0) | deque.popleft() | 배수 |
  |---|---|---|---|
  | 10,000 | 0.0050s | 0.0002s | 29x |
  | 50,000 | 0.1114s | 0.0010s | 112x |
  | 100,000 | 0.4186s | 0.0020s | 212x |
  | 200,000 | 1.7785s | 0.0041s | 429x |

  - N이 2배가 되면 list는 약 4배(O(n²)), deque는 약 2배(O(n)) → 이론과 일치
  - list는 앞을 빼면 뒤 원소를 전부 한 칸씩 당겨야 해서 1번에 O(n), BFS 큐처럼 N번 반복하면 O(n²)
  - 앞에서 넣고 빼는 구조(큐)는 `collections.deque`

## ② 해시

### 배운 것
- 해시: 값을 **번호표(해시 함수)로 바꿔서 그 자리로 바로 가는** 방식 → 있는지 확인이 **O(1)**. list는 처음부터 훑어서 O(n)
- 자료형별 용도

  | 자료형 | 용도 | 만드는 법 |
  |---|---|---|
  | `set` | 중복 제거, 있는지 확인 | `set(nums)`, `x in s` |
  | `dict` | 키 → 값, 키로 바로 찾기 | `d[키] = 값`, `d.get(키, 기본값)` |
  | `Counter` | 각 값이 몇 번 나왔나 | `Counter(seq)`, `c[키]`(없으면 0), `c.most_common(n)` |

- 시간복잡도

  | 연산 | list | set / dict |
  |---|---|---|
  | `x in ...` | O(n) | **O(1)** |
  | 추가 | O(1) (끝) | O(1) |

  - 값이 list 뒤쪽에 있을수록 차이가 커짐. set을 만드는 데 O(n)이 들어서 **여러 번** 확인할 때 이득
- 키는 immutable만 가능 (`(x, y)` tuple OK, `[x, y]` list는 `TypeError: unhashable type`)
- `d[키] = 값`은 없으면 추가, 있으면 덮어씀 (같은 키가 중복으로 오면 마지막 값만 남음)
- `Counter` 끼리는 `-`가 됨 (0 이하는 사라짐), 일반 dict는 `TypeError`
- `zip(a, b)`, `enumerate(seq)`는 이터레이터 → 보려면 `list(...)`, 한 번 쓰면 비어 있음
- 코테 신호: "있는지 확인" → `set` / "몇 번 나왔나" → `Counter` / "짝 찾기" → `dict`에 지나온 값 저장 / 이중 for문의 안쪽이 "찾기"뿐이면 해시로 O(1)

### 문제 풀이
| 문제 | 유형 / 핵심 아이디어 / 시간복잡도 / 틀린 이유 |
|---|---|
| 폰켓몬 (Lv.1) | 해시(set) / 답 = min(종류 수, 전체 마리 수 // 2) / O(n) / `nums // 2`로 list를 나눠서 `TypeError` → `len(nums) // 2` |
| 완주하지 못한 선수 (Lv.1) | 해시(Counter) / `Counter(participant) - Counter(completion)`으로 남은 1명 찾기, 동명이인도 횟수로 처리 / O(n) / (직접 적기) |

- 완주하지 못한 선수는 정렬 풀이(O(n log n))도 가능하지만, Counter가 O(n)으로 더 빠름
- 두 수의 합 패턴(연습 5번): 이중 for문 O(n²) → `seen` dict에 `{값: 인덱스}`를 저장하며 한 번 순회 O(n). **확인 먼저, 저장은 나중에**

### 막혔던 점 / 해결
- `d.get(키, 기본값)` 인자 자리 → 첫 번째가 찾을 키, 두 번째가 없을 때 값
- `/`와 `//` → `/`는 항상 소수, `//`는 정수 몫. "몇 개"는 `//`
- list를 숫자처럼 나눔(`nums // 2`) → 나누려는 건 list가 아니라 개수 `len(nums)`
