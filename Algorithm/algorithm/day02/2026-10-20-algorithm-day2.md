## ① 스택

### 배운 것
- 스택: **나중에 넣은 게 먼저 나오는**(LIFO) 구조. 접시 쌓기. 파이썬에서는 `list`를 그대로 사용

  | 동작 | 코드 | 시간복잡도 | 반환 |
  |---|---|---|---|
  | 넣기 | `stack.append(x)` | O(1) | `None` |
  | 꺼내기 | `stack.pop()` | O(1) | 꺼낸 값 (list도 직접 줄어듦) |
  | 맨 위 보기 | `stack[-1]` | O(1) | 맨 위 값 (지우지 않음) |
  | 비었나 | `not stack` | O(1) | `True` / `False` |

  - 빈 스택에 `pop()`이나 `stack[-1]` → `IndexError` → 먼저 `if stack`/`if not stack`으로 확인
  - 끝에서 넣고 빼는 건 O(1), 앞에서 빼는 `pop(0)`은 O(n) (Day 1)
- 코테 신호: **짝을 맞춰야 할 때**(괄호), **방금 전 것과 비교해서 지울 때**(연속 중복 제거), 자기보다 큰 값이 나올 때까지(주식가격), 되돌리기
- 괄호 짝 맞추기가 스택인 이유: **가장 최근에 열린 것이 가장 먼저 닫혀야** 하므로 "마지막에 넣은 것을 먼저 꺼내는" 스택과 같음

  | `)`를 만났을 때 / 끝났을 때 | 의미 |
  |---|---|
  | `)`가 왔는데 스택이 **비었다** | 짝 없는 `)` → `False` (바로 끝) |
  | 끝났는데 스택에 **남았다** | 짝 없는 `(` → `False` |
  | 끝났고 스택이 **비었다** | `True` |

- 문자열은 immutable이라 `s.pop()`이 없음 → `list(s)`로 바꿔서 스택으로 사용
- **돌고 있는 list를 동시에 `pop()`으로 줄이면 반만 돈다** → 횟수는 `range(len(...))`로 미리 고정
- `return`은 값을 만드는 게 아니라 **함수를 즉시 끝내는** 명령
- 변수 이름으로 내장 이름(`str`, `list`, `dict`, `set`, `sum`, `max`, `min`, `len`, `input`)을 쓰지 않기
- `return a, b`는 `return (a, b)`와 같음 (쉼표로 나열하면 tuple)

### 문제 풀이
| 문제 | 유형 / 핵심 아이디어 / 시간복잡도 / 틀린 이유 |
|---|---|
| 같은 숫자는 싫어 (Lv.1) | 스택 / answer(스택)의 맨 위와 비교해서 **다를 때만** append / O(n) / 틀린 건 아니고 **돌아가는 구조**로 풀었음: "같으면 `pop()`으로 지우고 → 무조건 `append`"로 짰는데, 같은 값을 지웠다가 다시 넣는 거라 결과는 같지만 불필요한 동작. **"같은 걸 지운다"가 아니라 "다를 때만 넣는다"** 로 생각을 뒤집으면 `pop` 없이 `if not stack or stack[-1] != x: append` 한 줄로 끝남 |
| 올바른 괄호 (Lv.2) | 스택 / `(`는 쌓고 `)`는 꺼내서 짝 맞추기, 비었는데 `)`면 바로 `False`, 끝나고 `not stack` / O(n) / 연습 중 `)`에서 `return stack.pop()`으로 함수가 끝나 버림, 빈 스택 `stack[-1]`로 `IndexError` |

### 막혔던 점 / 해결
- 빈 스택에 `stack[-1]` → `IndexError`: 에러만 피하려고 `stack and ...`로 바꾸면 짝 없는 `)`가 무시돼 `"())"`가 `True`로 나옴 → **비었으면 바로 `return False`**
- `return False if not stack else stack.pop()`: 안 비었을 때도 `return`이라 함수가 끝남 → `if not stack: return False` 다음 줄에 `stack.pop()`
- `[chars.pop() for _ in chars]`: 돌면서 지워서 일부 글자가 빠짐 → `range(len(chars))`
- 자세한 기록은 [막혔던것.md](./막혔던것.md)
